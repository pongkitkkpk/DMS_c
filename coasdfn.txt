What the gates do

Each flagged transition enforces the limit that first becomes real at it, and never one that
is already committed: PROJECT_APPROVED → (a); BUDGET_APPROVED → (a)+(c); REPORT_SUBMITTED →
(b). Re-checking (c) at the report would let a lowered allocation block it, which Q33 says
must not happen. Everything that does not block is returned as budgetWarnings on every
transition and every read, so a problem is visible for the whole of the phase in which it can
still be fixed — that is Q26's "warn on draft submit", same evaluation, reported not enforced.

A refusal is 422, not 400: the request was well formed and the caller was entitled to make it,
the numbers refused it. The body carries every violation, not only the first.

The lock lesson from last night, applied again

Same REPEATABLE READ trap, same two mechanisms. Lock one existing row first to serialize, then
read the aggregate FOR UPDATE so it sees what the previous holder committed rather than the
snapshot taken before the wait. Lock order is allocation → project → club everywhere,
including inside performTransition, which takes the allocation lock before the project row so
an approval racing a transition queues instead of meeting it head-on.

Stressed separately: eight simultaneous approvals against a ceiling with room for three landed
exactly on the ceiling, three runs in a row, no deadlock escaping its retries.

Frontend

The budget panel is built and was driven in a real browser, not just compiled. Figures as a
tile row, the three limits as meters, both variants' line items editable, the disbursement
ledger. Which controls appear comes from budget.permissions, which the server computed by
asking the same assertions its writes run — the client never works it out from the role.

Three things the browser found that the compiler could not: two line tables side by side were
too narrow to show the total column, a disabled primary button fell back to Bootstrap's blue,
and a meter sitting exactly on its limit was drawn amber when exactly-on-plan is the normal
good case. All three fixed.
