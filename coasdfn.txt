ไฟล์แนบ — สิ่งสำคัญคือ "ไม่มี static mount"

ระบบเก่า mount โฟลเดอร์ uploads เป็น static file ใครเดาชื่อไฟล์ถูกก็ได้เอกสารของชมรมอื่นไป
โดยไม่ต้องมี token ไม่มีการตรวจ scope และไม่มีร่องรอย — leak ตระกูลเดียวกับ deviation 1
ตอนนี้ทุก byte ออกผ่าน handler ที่ผ่าน loadProject มาแล้วเท่านั้น

- ชื่อไฟล์จากผู้ใช้เป็น "ป้าย" ไม่ใช่ path — ชื่อบนดิสก์ระบบสร้างเอง
  '../../../../evil.pdf' จึงไร้พิษ ทดสอบสองชั้น: ผ่าน HTTP และเรียก service ตรง ๆ
  ด้วยชื่อที่ไม่ผ่านการ sanitise ของ client เลย
- path ที่เก็บเป็น relative และ resolve ใต้ root เดียว (fix ไว้ใน config ครั้งเดียว)
- ดาวน์โหลดเป็น octet-stream + attachment + nosniff เสมอ ไฟล์ .html/.svg
  ที่อัปโหลดเข้ามาจึงรันเป็นสคริปต์ใน origin ของแอปไม่ได้
- ชนิดไฟล์เป็น allow-list ไม่ใช่ deny-list

เจอบั๊กจริงหนึ่งตัว: multer อ่าน filename ใน multipart header เป็น latin1 ชื่อไฟล์ไทย
'เอกสารแนบ.pdf' เลยกลายเป็น 'à¹à¸­à¸...' ในระบบที่คนตั้งชื่อไฟล์เป็นไทย นี่คือชื่อไฟล์
ทุกไฟล์ผิดหมด แก้ด้วย repairMultipartFilename() — ตีความ byte ใหม่ แบบมีการ์ด
(ASCII ไม่แตะ, ถ้าไม่ใช่ UTF-8 ที่ถูกต้องก็ปล่อยไว้)
