# DMS — ระบบโครงการกิจกรรมนักศึกษา (rebuild)

ระบบรับ–อนุมัติ–เบิกจ่าย–ปิดโครงการกิจกรรมนักศึกษา มจพ. เขียนใหม่จากระบบเดิม
โดยยังออกเอกสารราชการสองใบเหมือนเดิม คือ **กนศ.04** (แบบเสนอโครงการ) และ
**กนศ.06** (แบบรายงานผล)

> **นี่คือระบบสาธิต (demonstration system)** — ตั้งใจให้จบที่ `AUTH_PROVIDER=mock`
> ไม่ต่อกับระบบยืนยันตัวตนจริงของ ICIT ดูเหตุผลใน `docs/DECISIONS.md` (Q3, Q17)

---

## เริ่มใช้งาน

ต้องมี **Node.js 18 ขึ้นไป** (ใช้ `fetch` ในตัว) และ **MariaDB / MySQL**
(เครื่องที่พัฒนาใช้ MySQL ของ XAMPP)

```bash
# 1. เปิด MySQL จาก XAMPP control panel ก่อน แล้วสร้างฐานข้อมูลชื่อ dms

# 2. backend
cd backend
npm install
cp .env.example .env          # แก้ DB_PASS และ JWT_SECRET ให้เป็นของเครื่องตัวเอง
npm run db:reset              # สร้างตารางทั้งหมด + ใส่ข้อมูลตั้งต้น
npm start                     # http://localhost:3001

# 3. frontend (อีกหน้าต่างหนึ่ง)
cd frontend
npm install
npm start                     # http://localhost:3000
```

**เปิด MySQL ก่อนเปิด backend เสมอ** ถ้า backend ขึ้นก่อน มันจะยังเดาปีการศึกษา
จากวันที่ไปพลาง ๆ และทุกบัญชีจะยังไม่มีสิทธิ์จนกว่ามันจะอ่านค่าจริงได้ (มันลองใหม่
เองทุก 5 วินาที และ `GET /api/health` บอกสถานะนี้ไว้ที่ `academicYearResolved`)

### บัญชีทดลอง

ใช้ mock provider — **รหัสผ่านอะไรก็ได้** หน้าล็อกอินแสดงรายชื่อไว้ให้แล้ว

| ชื่อผู้ใช้ | บทบาท | ทำอะไรได้ |
| --- | --- | --- |
| `fixture.student` | SH — หัวหน้าชมรม | สร้างและแก้โครงการของชมรมตัวเอง |
| `fixture.advisor` | AD — อาจารย์ที่ปรึกษา | อ่านโครงการของชมรมที่ตนดูแล |
| `fixture.stuact` | STUACT — เจ้าหน้าที่กิจการนักศึกษา | อนุมัติโครงการและวงเงิน จ่ายเงิน |
| `fixture.admin` | ADMIN — ผู้ดูแลระบบ | ทุกอย่าง รวมถึงกำหนดสิทธิ์และเปลี่ยนปีการศึกษา |
| `fixture.otherstudent` | SH ของอีกชมรม | มีไว้พิสูจน์ว่าข้อมูลข้ามชมรมไม่รั่ว |

## คำสั่งที่ใช้บ่อย (ใน `backend/`)

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm run db:reset` | ล้างและสร้างฐานข้อมูลใหม่พร้อมข้อมูลตั้งต้น |
| `npm run check:all` | ชุดตรวจทั้งหมด 407 ข้อ (ต้องเปิด API ไว้ก่อน — มันรีซีดให้เองระหว่าง suite) |
| `npm run forms:read -- --project <id>` | เรนเดอร์ฟอร์มของโครงการนั้นออกมาเป็นข้อความ อ่านได้โดยไม่ต้องเปิด Word |
| `npm run forms:review` | สร้างโครงการที่กรอกเต็มทุกช่องแล้วเซฟไฟล์ `.docx` ทั้งสองใบไว้ที่ `generated/forms/` |
| `npm run grant:admin -- --user <id_student> --year <ปี>` | ทางออกฉุกเฉินเมื่อปีการศึกษาไม่มีผู้ดูแลระบบเหลืออยู่ |

## โครงสร้าง

```
backend/     Express + mysql2 — API, กฎการเงิน, ตัวประกอบเอกสาร (assembler)
frontend/    React 18 (CRA) + Bootstrap 4 — ทุกหน้าจอ, ข้อความไทยฝังในโค้ด
templates/   ไฟล์ .docx ต้นฉบับของ กนศ.04 และ กนศ.06
docs/        เอกสารกำกับการตัดสินใจทั้งหมด — อ่านก่อนแก้อะไรที่กระทบพฤติกรรม
generated/   ผลลัพธ์ที่สคริปต์สร้าง (ไม่ถูก commit)
```

## เอกสาร

โฟลเดอร์ `docs/` ไม่ใช่คู่มือใช้งาน แต่คือ**บันทึกว่าทำไมระบบถึงเป็นแบบนี้**
ถ้าจะแก้พฤติกรรมของระบบ ให้เริ่มที่นี่

| ไฟล์ | ตอบเรื่องอะไร |
| --- | --- |
| `docs/DECISIONS.md` | ทุกการตัดสินใจ (Q1–Q41) รายการที่ตั้งใจทำต่างจากระบบเดิม และเรื่องที่ยังค้าง |
| `docs/business-rules.md` | ระบบเดิมบังคับกฎอะไรบ้าง พร้อม `file:line` |
| `docs/domain-model.md` | คำศัพท์และเอนทิตีของโดเมน |
| `docs/schema-current.md` | ฐานข้อมูลเดิม 15 ตาราง 843 คอลัมน์ และข้อบกพร่อง 11 จุด |
| `docs/schema-target.md` | ฐานข้อมูลใหม่ พร้อมแผนที่ว่าคอลัมน์เดิมไปอยู่ไหน |
| `docs/template-contract.md` | แท็กในฟอร์ม Word ทั้ง 1,426 + 241 ตัว และจำนวนแถวสูงสุดของแต่ละตาราง |
| `DMS_REBUILD_STRATEGY.md` | ลำดับการสร้าง และบันทึกสิ่งที่พบระหว่างทางของแต่ละรอบงาน |

สองกฎที่ใช้ตลอดทั้งโปรเจกต์: **ระบบเดิมคือสเปกของพฤติกรรม** (Q2) และ
**ข้อบกพร่องด้านความปลอดภัยหรือความถูกต้องให้แก้และบันทึกไว้ ไม่แก้เงียบ ๆ** (Q22)
