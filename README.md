# DMS — ระบบโครงการกิจกรรมนักศึกษา (rebuild)

ระบบรับ–อนุมัติ–เบิกจ่าย–ปิดโครงการกิจกรรมนักศึกษา มจพ. เขียนใหม่จากระบบเดิม
โดยยังออกเอกสารราชการสองใบเหมือนเดิม คือ **กนศ.04** (แบบเสนอโครงการ) และ
**กนศ.06** (แบบรายงานผล)

> **นี่คือระบบสาธิต (demonstration system)** — ตั้งใจให้จบที่ `AUTH_PROVIDER=mock`
> ไม่ต่อกับระบบยืนยันตัวตนจริงของ ICIT ดูเหตุผลใน `docs/DECISIONS.md` (Q3, Q17)

## เริ่มใช้งาน

ต้องมี **Node.js 18 ขึ้นไป** (ใช้ `fetch` ในตัว) และ **MariaDB / MySQL**
(เครื่องที่พัฒนาใช้ MySQL ของ XAMPP)

```bash
# 1. เปิด MySQL จาก XAMPP control panel ก่อน แล้วสร้างฐานข้อมูลชื่อ dms

# 2. backend
cd backend
npm install
cp .env.example .env          # แก้ DB_PASS และ JWT_SECRET ให้เป็นของเครื่องตัวเอง
npm run db:reset              # สร้างตารางทั้งหมด + ใส่ข้อมูลตั้งต้น
npm start                     # http://localhost:3001

# 3. frontend (อีกหน้าต่างหนึ่ง)
cd frontend
npm install
npm start                     # http://localhost:3000
```

**เปิด MySQL ก่อนเปิด backend เสมอ** ถ้า backend ขึ้นก่อน มันจะยังเดาปีการศึกษา
จากวันที่ไปพลาง ๆ และทุกบัญชีจะยังไม่มีสิทธิ์จนกว่ามันจะอ่านค่าจริงได้ (มันลองใหม่
เองทุก 5 วินาที และ `GET /api/health` บอกสถานะนี้ไว้ที่ `academicYearResolved`)

## ถ้าจะเอาขึ้นเซิร์ฟเวอร์จริง

**ตั้ง `NODE_ENV=production` เสมอ** ไม่ใช่เพื่อความเร็ว แต่เพราะชุดตรวจ config
ทั้งชุดทำงานเฉพาะตอนนั้น ถ้าไม่ตั้ง ระบบจะยอมให้ deploy ทั้งที่ฐานข้อมูลไม่มีรหัสผ่าน
origin เป็น plain http และประตูหลัง `ADMIN_USERNAME` ยังเปิดอยู่ โดยไม่บ่นสักคำ
เมื่อตั้งแล้ว `npm start` จะ **ไม่ยอมเปิด** จนกว่าทุกข้อจะเรียบร้อย และบอกมาเป็นข้อ ๆ ว่าขาดอะไร

สิ่งที่มันบังคับตอน production:

| ต้องมี | เพราะ |
| --- | --- |
| `JWT_SECRET` ยาว 32 ตัวอักษรขึ้นไป | โทเคนคือทั้งเซสชัน — ความลับที่เดาได้เท่ากับปลอมสิทธิ์ใครก็ได้ |
| `DB_PASS` ไม่ว่าง และ `DB_USER` ไม่ใช่ `root` | ฐานข้อมูลเก็บตาราง `membership` ที่ตัดสินว่าใครทำอะไรได้ |
| `CORS_ORIGIN` เป็น `https://` และระบุชื่อจริง | โทเคนเดินทางบน http แบบเปิดเผยให้ใครก็ตามที่อยู่ระหว่างทางอ่านได้ |
| `MOCK_PASSWORD` + `ALLOW_MOCK_AUTH=1` | `fixture.admin` เป็นชื่อผู้ใช้ที่เขียนไว้ในโค้ด — ถ้าไม่ตั้งรหัสร่วม ใครเจอ URL ก็เข้าเป็นผู้ดูแลระบบได้ |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` ต้องว่าง | ประตูหลัง Q17 มีไว้สำหรับเครื่องพัฒนาเท่านั้น |

ถ้ามี nginx หรือ reverse proxy คั่นอยู่ ให้ตั้ง `TRUST_PROXY=1` ด้วย มิฉะนั้น
`req.ip` จะเป็นที่อยู่ของ proxy ทั้งหมด แล้วโควตาการเดารหัสผ่านต่อ IP
(`LOGIN_MAX_PER_ADDRESS`) จะกลายเป็นโควตาเดียวที่ทุกคนใช้ร่วมกัน — ตั้งเป็นจำนวน hop
ที่เราคุมเองจริง ๆ ไม่ใช่ `true`

สองอย่างที่ระบบไม่ได้ทำให้ และต้องทำที่ชั้นอื่น: **TLS** (ให้ reverse proxy ถือใบรับรอง)
และ **การสำรองข้อมูล** (`uploads/` กับฐานข้อมูลต้องถูกสำรองคู่กัน — แถวในตาราง
`project_attachment` ที่ไม่มีไฟล์จริงจะตอบ 404 ไม่ใช่พัง แต่ก็คือไฟล์ที่หายไปอยู่ดี)

## โครงสร้าง

```
backend/     Express + mysql2 — API, กฎการเงิน, ตัวประกอบเอกสาร (assembler)
frontend/    React 18 (CRA) + Bootstrap 4 — ทุกหน้าจอ, ข้อความไทยฝังในโค้ด
templates/   ไฟล์ .docx ต้นฉบับของ กนศ.04 และ กนศ.06
docs/        เอกสารกำกับการตัดสินใจทั้งหมด — อ่านก่อนแก้อะไรที่กระทบพฤติกรรม
generated/   ผลลัพธ์ที่สคริปต์สร้าง (ไม่ถูก commit)
```

## เอกสาร

ถ้าจะแก้พฤติกรรมของระบบ ให้เริ่มที่นี่

| `docs/DECISIONS.md` | ทุกการตัดสินใจ (Q1–Q41) รายการที่ตั้งใจทำต่างจากระบบเดิม และเรื่องที่ยังค้าง |

| `docs/schema-target.md` | ฐานข้อมูลใหม่ พร้อมแผนที่ว่าคอลัมน์เดิมไปอยู่ไหน |
